HTML을 작성하다 보면 생각한 대로 화면에 표시되지 않을 때가 있습니다. 브라우저 개발자 도구(DevTools)를 쓰면 HTML 구조, 스타일 적용 여부, 네트워크 오류를 한눈에 확인할 수 있습니다. F12 키 하나로 열 수 있으며 VS Code처럼 별도 설치가 필요 없습니다.

---

## 개발자 도구 여는 법

| 브라우저 | 단축키 |
|----------|--------|
| Chrome | `F12` 또는 `Ctrl + Shift + I` |
| Edge | `F12` 또는 `Ctrl + Shift + I` |
| Firefox | `F12` 또는 `Ctrl + Shift + I` |
| Safari | `Cmd + Option + I` (환경설정에서 개발자 메뉴 활성화 필요) |

가장 빠른 방법은 확인하고 싶은 요소 위에서 마우스 오른쪽 버튼을 클릭하고 "검사(Inspect)"를 선택하는 것입니다. 해당 요소가 선택된 상태로 Elements 패널이 열립니다.

---

## Elements 패널에서 HTML 보기

개발자 도구를 열면 기본으로 Elements(요소) 패널이 표시됩니다. 여기서 현재 페이지의 전체 HTML 구조를 볼 수 있습니다.

```html
<!-- 브라우저에 표시된 대로 -->
<html>
  <head>...</head>
  <body>
    <h1>안녕하세요</h1>
    <p>반갑습니다.</p>
  </body>
</html>
```

Elements 패널에서 볼 수 있는 정보:

- **태그 구조**: 중첩된 HTML이 트리 형태로 표시됩니다
- **닫는 태그 누락**: 닫는 태그가 없으면 브라우저가 임의로 닫아버린 위치를 확인 가능
- **인라인 스타일**: 태그의 `style` 속성이 바로 보입니다
- **클래스와 아이디**: 각 요소에 붙은 클래스명과 아이디를 확인할 수 있습니다

---

## Elements 패널에서 HTML 직접 수정하기

Elements 패널의 HTML은 읽기 전용이 아니고 **직접 편집**할 수 있습니다.

**요소 더블 클릭** — 태그명, 속성값, 텍스트를 그 자리에서 수정할 수 있습니다. 수정한 내용은 브라우저 화면에 즉시 반영됩니다.

```html
<!-- 수정 전 -->
<h1>안녕하세요</h1>

<!-- h1을 더블 클릭하고 '반갑습니다'로 변경하면 -->
<h1>반갑습니다</h1>
```

편집한 내용은 브라우저에만 반영되고 원본 HTML 파일은 바뀌지 않습니다. 새로고침하면 원래대로 돌아옵니다. 이 기능은 "이 텍스트를 바꾸면 레이아웃이 어떻게 바뀔까"를 실험해볼 때 유용합니다.

**요소 삭제**: Elements 패널에서 요소를 선택하고 `Delete` 키를 누르면 해당 요소가 화면에서 사라집니다. "이 div를 지우면 아래 내용이 위로 올라올까?" 같은 궁금증을 바로 확인할 수 있습니다.

---

## 태그가 제대로 닫혔는지 확인하는 법

HTML에서 닫는 태그를 빼먹으면 브라우저가 임의로 해석해서 레이아웃이 깨집니다.

```html
<!-- 실수: p 태그 닫는 태그 누락 -->
<div>
  <p>첫 번째 문단
  <p>두 번째 문단</p>
</div>
```

Elements 패널에서 확인해보면 브라우저가 자동으로 `</p>`를 넣은 위치를 볼 수 있습니다. 원하는 위치와 다르다면 직접 `</p>`를 추가해야 합니다. 개발자 도구에서 수정해보고 의도대로 표시되면 원본 파일을 고치면 됩니다.

---

## JavaScript로 생성된 HTML 확인

JavaScript로 동적으로 생성된 HTML도 Elements 패널에서 볼 수 있습니다.

```javascript
// 이 코드로 생성된 요소는
document.getElementById('app').innerHTML = '<p class="dynamic">동적으로 추가됨</p>';
```

Elements 패널에서 `#app` 안에 `<p class="dynamic">`이 나타난 것을 확인할 수 있습니다. JavaScript가 실제로 의도한 HTML을 생성했는지, 클래스명이 올바른지 등을 바로 확인할 수 있습니다. 페이지 소스 보기(View Page Source)로는 JavaScript로 추가된 내용을 볼 수 없지만, Elements 패널에서는 실시간 DOM 상태를 보여주기 때문에 가능합니다.

## 자주 쓰는 디버깅 팁

**1. 404 오류 확인하기**

이미지나 CSS 파일이 로드되지 않을 때는 Console(콘솔) 패널을 봅니다.

```
GET https://example.com/style.css 404 (Not Found)
GET https://example.com/logo.png 404 (Not Found)
```

Network(네트워크) 패널에서도 상태 코드를 확인할 수 있습니다. 빨간색으로 표시된 항목이 오류가 있는 파일입니다. 파일 경로에 오타가 없는지, 대소문자가 맞는지 확인합니다. 서버에서는 대소문자를 구분하는 경우가 많습니다.

**2. 스타일이 적용되지 않는 태그 찾기**

Elements 패널에서 요소를 선택한 다음 오른쪽 Styles 탭을 보면 적용된 CSS와 적용되지 않은 CSS(취소선 표시)를 모두 볼 수 있습니다. 적용되지 않은 이유는 보통 선택자 우선순위나 상속 문제 때문입니다.

**3. aria 속성 확인**

접근성 관련 `aria-label`, `role` 속성이 올바르게 적용됐는지 Elements 패널에서 바로 확인할 수 있습니다.

## 실습: 직접 디버깅해보기

아래 HTML 파일을 만들고 브라우저로 연 다음 F12를 눌러보세요.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>디버깅 실습</title>
</head>
<body>
  <h1>개발자 도구 실습</h1>
  <p>이 문단을 선택하고 F12를 눌러보세요.
  <img src="없는파일.jpg" alt="이 이미지는 로드되지 않습니다">
  <ul>
    <li>첫 번째</li>
    <li>두 번째
    <li>세 번째</li>
  </ul>
</body>
</html>
```

Elements 패널에서 다음을 확인합니다.

- 두 번째 li의 닫는 태그가 없는데 브라우저가 어떻게 처리하는지
- 이미지가 로드되지 않았다는 콘솔 오류 메시지
- h1 태그를 더블 클릭해서 텍스트를 직접 바꿔보기

파일의 오타를 수정할 때마다 새로고침해서 결과가 어떻게 달라지는지 비교해보면 디버깅 감각이 생깁니다.

---

## 되짚기

- F12 또는 마우스 우클릭 → 검사로 개발자 도구 열기
- Elements 패널에서 HTML 구조 확인 및 실시간 편집 가능
- 페이지 소스 보기와 달리 JavaScript로 생성된 DOM도 볼 수 있음
- Console 패널에서 네트워크 오류(404) 확인
- 수정한 내용은 새로고침 시 사라짐 (원본 파일 직접 수정 필요)

다음 글에서는 프로젝트 규모가 커졌을 때 HTML 폴더와 파일 구조를 어떻게 설계하는지 알아봅니다.
