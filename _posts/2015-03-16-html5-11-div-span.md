HTML을 처음 배울 때 div 태그로 모든 것을 감싸는 코드를 많이 보게 됩니다. 왜냐하면 일단 div로 묶으면 CSS로 스타일을 적용하기 편하기 때문입니다. 하지만 div와 span을 무분별하게 쓰면 코드의 의미가 불분명해지고, 검색 엔진이나 스크린 리더가 페이지를 이해하기 어려워집니다.

div와 span이 존재 이유를 정리해보겠습니다. 브라우저에서 직접 코드를 실행해보면 블록과 인라인의 차이가 한눈에 보입니다.

---

## 블록 요소 vs 인라인 요소

HTML 태그는 크게 두 가지 성질을 가집니다.

**블록 요소 (Block Element)**
- 항상 새 줄에서 시작합니다
- 가로 너비가 부모 요소의 100%를 차지합니다
- 대표 태그: `div`, `p`, `h1`~`h6`, `ul`, `table`, `form`

**인라인 요소 (Inline Element)**
- 텍스트 흐름 안에서 이어집니다 (줄 바꿈 없음)
- 내용만큼만 너비를 차지합니다
- 대표 태그: `span`, `a`, `strong`, `em`, `img`

```html
<!-- 블록 요소: 각각 새 줄에서 시작 -->
<div>첫 번째 div</div>
<div>두 번째 div</div>

<!-- 인라인 요소: 같은 줄에 이어서 표시 -->
<span>첫 번째</span>
<span>두 번째</span>
<span>세 번째</span>
```

직접 브라우저에서 열어보면 차이가 바로 보입니다. div는 각각이 줄바꿈되어 세로로 쌓이고, span은 가로로 죽 이어져서 한 줄에 표시됩니다. 이 동작 차이가 CSS 레이아웃의 가장 기본이 되는 개념입니다.

---

## div — 블록 레벨 컨테이너

자체적인 의미는 없고, 요소를 그룹으로 묶을 때 사용합니다.

```html
<div class="card">
  <div class="card-header">
    <h2>JavaScript 비동기 처리</h2>
    <span class="badge">중급</span>
  </div>
  <div class="card-body">
    <p>Promise와 async/await의 차이를 실습 예제로 설명합니다.</p>
  </div>
  <div class="card-footer">
    <a href="/post/1">더 읽기</a>
  </div>
</div>
```

div는 CSS 클래스와 함께 쓰여야 의미를 가집니다. div에 `class`나 `id`가 없다면 시맨틱 태그(`header`, `section`, `article` 등)를 쓰는 게 더 적절할 수 있습니다.

---

## span — 인라인 컨테이너

텍스트 일부에 CSS를 적용하거나 JavaScript로 접근할 때 사용합니다.

```html
<!-- 가격에만 색상 적용 -->
<p>현재 가격: <span class="price">29,000원</span></p>

<!-- 강조 단어에 배경색 적용 -->
<p>이 함수는 <span class="highlight">비동기</span>로 동작합니다.</p>

<!-- JavaScript로 특정 텍스트 접근 -->
<p>현재 접속자: <span id="visitor-count">0</span>명</p>
```

## div 남용 문제 — div soup

초보자들이 자주 하는 실수가 모든 것을 div로 감싸는 것입니다.

```html
<!-- div soup: 읽기 어렵고 의미가 없는 구조 -->
<div>
  <div>
    <div>제목</div>
    <div>
      <div>본문 내용</div>
      <div>작성일</div>
    </div>
  </div>
</div>

<!-- 의미 있는 구조 -->
<article>
  <header>
    <h2>제목</h2>
  </header>
  <p>본문 내용</p>
  <time datetime="2024-01-01">2024년 1월 1일</time>
</article>
```

의미 있는 시맨틱 태그를 먼저 고려하고, 적합한 태그가 없을 때 div를 씁니다.

## 블록 안에 인라인, 인라인 안에 블록 규칙

인라인 요소 안에 블록 요소를 넣으면 안 됩니다.

```html
<!-- 잘못된 중첩: span(인라인) 안에 div(블록) -->
<span>
  <div>잘못된 구조</div>
</span>

<!-- 올바른 중첩: div(블록) 안에 span(인라인) -->
<div>
  <span>올바른 구조</span>
</div>
```

단, `<a>` 태그는 HTML5에서 블록 요소를 감쌀 수 있도록 허용됩니다.

```html
<!-- HTML5에서 허용 -->
<a href="/post/1">
  <div class="card">
    <h2>카드 전체가 클릭 가능</h2>
    <p>이미지, 제목, 설명 모두 포함</p>
  </div>
</a>
```

## 요약

- `div` — 블록 요소 컨테이너, 새 줄에서 시작, 전체 너비 차지
- `span` — 인라인 컨테이너, 텍스트 흐름 안에서 사용
- 블록 요소 안에 인라인 요소를 넣는 것이 올바른 중첩
- 의미 있는 시맨틱 태그를 먼저 고려하고, 없을 때 div 사용

다음 글에서는 시맨틱 태그 (header, nav, main, section, article, footer)를 다룹니다.

## 자주 하는 실수와 주의점

초보자들이 div와 span 태그을 다룰 때 가장 흔히 하는 실수는 닫는 태그를 빼먹거나 속성값을 따옴표로 감싸지 않는 것입니다. HTML은 오류에 관대한 편이지만, 이런 실수는 레이아웃이 깨지거나 스타일이 정상적으로 적용되지 않는 원인이 됩니다. 반드시 모든 태그가 올바르게 열고 닫혔는지, 속성값은 따옴표로 감쌌는지 확인하는 습관을 들이는 것이 좋습니다.

## 브라우저 동작 방식

브라우저는 HTML 문서를 위에서 아래로 읽으며 DOM(Document Object Model) 트리를 생성합니다. div와 span 태그 요소가 DOM 트리에서 어떻게 해석되고 배치되는지 이해하면 더 체계적인 마크업을 작성할 수 있습니다. 개발자 도구(F12)의 Elements 패널을 열어 실제 DOM 구조를 확인하는 습관을 추천합니다.

## 실전 활용 팁

실무에서는 div와 span 태그을 단독으로 사용하기보다는 CSS와 JavaScript와 함께 조합하여 사용합니다. 시맨틱한 마크업은 검색 엔진 최적화(SEO)와 웹 접근성 향상에 직접적인 도움을 줍니다. 또한 W3C validator를 통해 HTML 문법을 검증하면 크로스 브라우징 이슈를 줄일 수 있습니다.
