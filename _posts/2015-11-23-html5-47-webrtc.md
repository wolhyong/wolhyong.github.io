WebRTC(Web Real-Time Communication)는 플러그인 없이 브라우저끼리 직접 영상, 음성, 데이터를 주고받는 기술입니다. 화상 회의, 화면 공유, P2P 파일 전송에 사용됩니다.

---

## WebRTC 핵심 구성 요소

| 개념 | 설명 |
|------|------|
| **P2P** | 서버 중계 없이 브라우저 간 직접 통신 |
| **SDP** | 연결 협상 정보 (코덱, 해상도, 네트워크 등) |
| **ICE** | 최적 네트워크 경로 탐색 |
| **STUN** | 공인 IP/포트 확인 서버 |
| **TURN** | P2P 불가 시 중계 서버 |
| **Signaling** | Offer/Answer 교환 경로 (WebSocket 등) |

P2P 연결을 맺으려면 먼저 WebSocket이나 HTTP로 **시그널링(SDP, ICE candidate 교환)** 을 해야 합니다.

## getUserMedia — 카메라/마이크 접근

```javascript
// 영상 + 음성
const stream = await navigator.mediaDevices.getUserMedia({
  video: {
    width: { ideal: 1280 },
    height: { ideal: 720 },
    facingMode: 'user' // 'user' = 전면, 'environment' = 후면
  },
  audio: {
    echoCancellation: true,
    noiseSuppression: true,
    sampleRate: 48000
  }
});

// video 요소에 스트림 연결
const localVideo = document.getElementById('local-video');
localVideo.srcObject = stream;
localVideo.muted = true; // 로컬 오디오 에코 방지

// 트랙 정보 확인
const videoTrack = stream.getVideoTracks()[0];
console.log(videoTrack.getSettings()); // 실제 적용된 해상도 등

// 카메라/마이크 중지
function stopStream(stream) {
  stream.getTracks().forEach(track => track.stop());
}
```

```html
<video id="local-video" autoplay playsinline muted></video>
```

## RTCPeerConnection — P2P 연결

완전한 1:1 영상 통화를 구현하려면 시그널링 서버가 필요합니다. 여기서는 과정을 이해하기 위한 단계별 코드를 설명합니다.

```javascript
// ICE 서버 설정 (STUN 서버)
const iceConfig = {
  iceServers: [
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'stun:stun1.l.google.com:19302' },
    // TURN 서버 (방화벽 환경용, 비용 발생)
    // { urls: 'turn:turn.example.com', username: 'user', credential: 'pass' }
  ]
};

// 연결 생성
const pc = new RTCPeerConnection(iceConfig);

// 로컬 미디어 스트림 추가
const localStream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
localStream.getTracks().forEach(track => pc.addTrack(track, localStream));

// 원격 스트림 수신
pc.addEventListener('track', (event) => {
  const remoteVideo = document.getElementById('remote-video');
  remoteVideo.srcObject = event.streams[0];
});

// ICE 후보 수집 → 시그널링 서버로 전송
pc.addEventListener('icecandidate', (event) => {
  if (event.candidate) {
    signalingServer.send(JSON.stringify({
      type: 'ice-candidate',
      candidate: event.candidate
    }));
  }
});
```

**Offer 생성 (발신자)**

```javascript
// 1. Offer SDP 생성
const offer = await pc.createOffer();

// 2. 로컬 설명 설정
await pc.setLocalDescription(offer);

// 3. Offer를 시그널링 서버를 통해 상대방에게 전송
signalingServer.send(JSON.stringify({
  type: 'offer',
  sdp: offer
}));
```

**Answer 생성 (수신자)**

```javascript
// 시그널링 서버로부터 Offer 수신
signalingServer.addEventListener('message', async (event) => {
  const msg = JSON.parse(event.data);

  if (msg.type === 'offer') {
    // 1. 원격 설명 설정
    await pc.setRemoteDescription(new RTCSessionDescription(msg.sdp));

    // 2. Answer 생성
    const answer = await pc.createAnswer();
    await pc.setLocalDescription(answer);

    // 3. Answer 전송
    signalingServer.send(JSON.stringify({ type: 'answer', sdp: answer }));
  }

  if (msg.type === 'answer') {
    await pc.setRemoteDescription(new RTCSessionDescription(msg.sdp));
  }

  if (msg.type === 'ice-candidate') {
    await pc.addIceCandidate(new RTCIceCandidate(msg.candidate));
  }
});
```

## RTCDataChannel — 데이터 전송

영상/음성 없이 순수하게 데이터만 P2P로 전송할 수 있습니다.

```javascript
// 발신자: 데이터 채널 생성
const dataChannel = pc.createDataChannel('chat', {
  ordered: true,       // 순서 보장
  maxRetransmits: 3    // 재전송 횟수
});

dataChannel.addEventListener('open', () => {
  console.log('데이터 채널 열림');
  dataChannel.send(JSON.stringify({ type: 'hello', message: '안녕하세요!' }));
});

dataChannel.addEventListener('message', (event) => {
  console.log('수신:', JSON.parse(event.data));
});

// 수신자: 데이터 채널 이벤트
pc.addEventListener('datachannel', (event) => {
  const channel = event.channel;
  channel.addEventListener('message', (e) => {
    console.log('수신:', JSON.parse(e.data));
  });
});
```

```html
    video { max-width: 640px; width: 100%; border-radius: 8px; background: #161b22; }
    .controls { margin-top: 16px; display: flex; gap: 8px; justify-content: center; }
    button { padding: 8px 20px; border: none; border-radius: 6px; cursor: pointer; }

    #stop  { background: #da3633; color: white; }
  </style>
</head>

  <h1>카메라 테스트</h1>
  <video id="video" autoplay playsinline muted></video>
  <div class="controls">
    <button id="start">카메라 시작</button>
    <button id="stop" disabled>카메라 중지</button>
  </div>
  <p id="status">카메라 꺼짐</p>

  <script>
    let stream = null;

    document.getElementById('start').addEventListener('click', async () => {
      try {
        stream = await navigator.mediaDevices.getUserMedia({
          video: { width: { ideal: 640 }, height: { ideal: 480 } },
          audio: false
        });
        document.getElementById('video').srcObject = stream;
        document.getElementById('status').textContent = '카메라 켜짐 ●';
        document.getElementById('start').disabled = true;
        document.getElementById('stop').disabled = false;
      } catch (err) {
        const messages = {
          NotAllowedError: '카메라 권한이 거부됐습니다.',
          NotFoundError: '카메라를 찾을 수 없습니다.',
          NotReadableError: '카메라가 이미 사용 중입니다.',
        };
        document.getElementById('status').textContent = messages[err.name] || err.message;
      }
    });

    document.getElementById('stop').addEventListener('click', () => {
      stream?.getTracks().forEach(t => t.stop());
      document.getElementById('video').srcObject = null;
      document.getElementById('status').textContent = '카메라 꺼짐';
      document.getElementById('start').disabled = false;
      document.getElementById('stop').disabled = true;
    });
  </script>
</body>
</html>
```

## 마치며
- `getUserMedia`로 카메라·마이크·화면에 접근합니다
- `RTCPeerConnection`으로 P2P 연결을 맺습니다
- Offer/Answer/ICE 교환은 시그널링 서버(WebSocket 등)를 통해 이루어집니다
- `RTCDataChannel`로 영상 없이 P2P 데이터 전송을 구현합니다
- STUN 서버로 공인 IP를 확인하고, 방화벽 환경에서는 TURN 서버가 필요합니다

다음 글에서는 HTML 보안 기초 — XSS 방어, CSP 헤더, CSRF를 다룹니다.

## 자주 하는 실수와 주의점

초보자들이 WebRTC 기초을 다룰 때 가장 흔히 하는 실수는 닫는 태그를 빼먹거나 속성값을 따옴표로 감싸지 않는 것입니다. HTML은 오류에 관대한 편이지만, 이런 실수는 레이아웃이 깨지거나 스타일이 정상적으로 적용되지 않는 원인이 됩니다. 반드시 모든 태그가 올바르게 열고 닫혔는지, 속성값은 따옴표로 감쌌는지 확인하는 습관을 들이는 것이 좋습니다.

## 브라우저 동작 방식

브라우저는 HTML 문서를 위에서 아래로 읽으며 DOM(Document Object Model) 트리를 생성합니다. WebRTC 기초 요소가 DOM 트리에서 어떻게 해석되고 배치되는지 이해하면 더 체계적인 마크업을 작성할 수 있습니다. 개발자 도구(F12)의 Elements 패널을 열어 실제 DOM 구조를 확인하는 습관을 추천합니다.

## 실전 활용 팁

실무에서는 WebRTC 기초을 단독으로 사용하기보다는 CSS와 JavaScript와 함께 조합하여 사용합니다. 시맨틱한 마크업은 검색 엔진 최적화(SEO)와 웹 접근성 향상에 직접적인 도움을 줍니다. 또한 W3C validator를 통해 HTML 문법을 검증하면 크로스 브라우징 이슈를 줄일 수 있습니다.
